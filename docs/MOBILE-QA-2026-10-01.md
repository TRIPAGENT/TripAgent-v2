# Mobile customer review — 1 October 2026

## Scope

Reviewed the live sign-in and invitation pages in headless Chrome with mobile viewport/touch emulation. The live backend rejected all three documented demo codes. Backend code confirms these seed accounts are local-only; production member journeys require an active test account from the Desk.

Ran the frontend against a separate local backend with disposable memory, using the documented Eleanor demo account. No production bookings, enquiries, or payments were submitted. No live AI response was tested: local model credentials were absent. Waiting-state checks used explicitly simulated delayed and streamed responses.

## Verified

- Demo sign-in and all five onboarding questions.
- Discover, Tokyo guide, Saved, Journeys, Membership, world map, Services, and Concierge render without JavaScript exceptions or horizontal overflow at 390 × 844.
- Saving Tokyo persists after a reload.
- Sign-out returns to the sign-in screen.
- All eight access-code cells fit at 320 × 740.
- Travel messages change during a delayed reply and during tool activity; a completed reply replaces the waiting state.
- The message input stays above the navigation at 390 × 844.
- Production build, TypeScript checks, bundle secrets scan, and diff whitespace check pass. Vite reports its existing large-chunk warning.

## Changes

- Flexible access-code cells fix clipping on narrow phones.
- Removed translation from the page-entry animation, which created a containing block for fixed controls and misplaced the chat composer.
- Travel-themed waiting messages rotate every 4.5 seconds, including while tools are working. Actual tool activity remains separately labelled.
- Added labels for destination, season, hotel-rate, and travel-note tools.
- Removed the unverified promise to notify customers after leaving the chat.
- Generic waiting status has a stable accessible label rather than announcing every changing travel phrase.
